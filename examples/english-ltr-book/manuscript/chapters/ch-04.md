# Chapter 4: Game Days That Actually Teach

An untested failover script is a bedtime story, not a recovery plan. Configurations drift. Credentials expire silently. New tables bypass old read-replica rules.

Schedule a forty-five-minute Game Day once a month during normal business hours while every engineer is awake and caffeinated:

1. **State a clear hypothesis:** *"Blocking traffic to the secondary pricing cache will raise p95 latency by at most 35 ms and trigger static fallback pricing within 5 seconds."*
2. **Define an instant abort switch:** Keep a single command ready to restore normal routing in under ten seconds if customer error rates cross 0.5%.
3. **Verify alerts as well as code:** Did the dashboard highlight the real culprit, or did on-call receive forty noisy symptoms?

}

## Pre-Release Resilience Checklist

Before promoting any critical service to production traffic, confirm four invariants:

- Every outbound network client sets an explicit connect and read timeout.
- Every mutating endpoint accepts an idempotency key and deduplicates replays.
- Queue sizes are strictly bounded and reject overflow with `HTTP 429` or `503`.
- Automated pre-release tests exercise at least one dependency timeout path.
