# Chapter 2: Queues Never Create Capacity

Engineers love putting queues in front of slow services. It feels tidy. Spikes go in, smooth work comes out.

Except a queue never manufactures a single CPU cycle. It only borrows time from impatient callers. When arrival rate exceeds service rate for more than a few seconds, an unbounded in-memory queue grows until every item reaching the worker has already timed out at the browser! You end up burning 100% of your database capacity computing answers for users who already left.

## Propagate Deadlines End-to-End

Pass an explicit deadline header on every internal RPC and check remaining budget before starting expensive work:

```python
import time

def handle_checkout(request_deadline_ms: int) -> dict:
    remaining_ms = request_deadline_ms - int(time.time() * 1000)
    if remaining_ms < 45:
        raise TimeoutError("Caller deadline expired; shedding stale request")
    return {"status": "accepted", "budget_ms": remaining_ms}
```

Combined with a small bounded queue (`max_depth = 128`), deadline propagation drops stale requests in microseconds and preserves full throughput for live customers.
