# الفصل الرابع: بوابات الفحص قبل الإطلاق والمراقبة الحية

كيف ينام فريق الهندسة مطمئناً ليلة إطلاق تحديث جديد؟ الإجابة ليست في التمني، بل في حزمة اختبار ذهبية تعمل آلياً مع كل تعديل على التعليمات أو الأدوات.

تبني الفرق الناضجة مجموعتين منفصلتين من الاختبارات قبل قبول أي دمج برمجي في الفرع الرئيسي:

1. **اختبارات العقود الحتمية:** تتحقق خلال ثوانٍ معدودة من سلامة المخططات `JSON Schema`، وصحة معالجة الأخطاء، واحترام حدود الصلاحيات دون استدعاء شبكي.
2. **حالات التقييم المرجعية (`Golden Evals`):** مئة سيناريو واقعي مستخلص من أعطال سابقة فعلية، نقيس عليها نسبة النجاح الصافية وزمن الاستجابة وتكلفة الرموز.

```json
{
  "eval_suite": "production-gate-v2",
  "min_pass_rate": 0.97,
  "max_p95_latency_ms": 1800,
  "zero_policy_violations": true
}
```

## قائمة المراجعة النهائية قبل النشر

قبل تحويل النظام إلى حركة المرور الحقيقية، راجع البنود الأربعة التالية بنداً بنداً:

- هل يملك كل إجراء كتابي أو مالي مفتاح تفرد يمنع التكرار عند إعادة المحاولة؟
- هل تسجل طبقة الرصد مدخلات ومخرجات كل أداة مع إخفاء البيانات الشخصية الحساسة؟
- هل يوجد قاطع دائرة (`Circuit Breaker`) يحوّل الطلبات إلى مسار احتياطي آمن إذا ارتفعت أخطاء المزود الخارجي فوق 5%؟
- هل جرى اختبار حالات الحافة باللغتين العربية والإنجليزية مع الأرقام والرموز المختلطة؟

متى اجتاز نظامك هذه البوابات الأربع معاً، انتقل من مجرد تجربة مثيرة للإعجاب إلى أصل هندسي يُعتمد عليه في قلب الإنتاج.
