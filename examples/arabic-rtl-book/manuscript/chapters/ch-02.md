# الفصل الثاني: فصل التخطيط عن التنفيذ الحتمي

لا تطلب من النموذج اللغوي أن يحسب عرض كعب كتاب أو رصيد حساب بنكي. اطلب منه فقط استخراج المعطيات وتحديد نية المستخدم، ثم اترك الرياضيات للكود الصرف.

هذا المبدأ البسيط يختصر نصف أعطال الإنتاج دفعة واحدة. النموذج اللغوي بارع في التعامل مع الغموض اللغوي وتلخيص النصوص غير المهيكلة، لكنه بطبيعته الإحصائية يولّد الرموز الأكثر ترجيحاً لا النتائج الحتمية.

## نموذج عقد الأداة الصارم

لكي تمنع الوكيل من تمرير معاملات ناقصة أو أنواع بيانات خاطئة، عرّف لكل أداة عقداً برمجياً واضحاً يتحقق من القيم قبل التنفيذ الفعلي:

```python
from dataclasses import dataclass

@dataclass(frozen=True)
class RefundCommand:
    order_id: str
    amount_cents: int
    idempotency_key: str

    def validate(self) -> None:
        if self.amount_cents <= 0 or self.amount_cents > 50_000:
            raise ValueError("Amount outside autonomous policy bounds")
        if not self.order_id.startswith("ORD-"):
            raise ValueError("Malformed order identifier")
```

لاحظ ما أنجزناه في بضعة أسطر برمجية قصيرة: حتى لو أخطأ النموذج تحت ضغط سياق طويل واقترح مبلغاً يتجاوز سقف الصلاحية التلقائية (`50000` قرش)، ترفض الدالة التنفيذ فوراً وتعيد رسالة خطأ واضحة توجه المسار نحو المراجعة البشرية.

## متى نستخدم الوكيل ومتى نكتفي بسير عمل ثابت؟

إذا كانت خطوات المهمة معروفة سلفاً بالترتيب نفسه في 95% من الحالات، فإن خط الأنابيب الثابت أسرع وأرخص وأسهل في الفحص بعشر مرات. احتفظ بالحلقة الوكيلية المفتوحة للمسائل التي يتوقف فيها اختيار الخطوة الثانية فعلياً على ما تكشفه نتيجة الخطوة الأولى.
